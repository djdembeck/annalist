Write a compact changelog for this release. Keep the whole output short and
scannable.

Use one line per change, in this order: new features first, then fixes, then
other changes. Each line is a single short phrase — a few words, not a full
sentence — that names what changed.

- One line per commit.
- Never merge two distinct changes into one line.
- Never omit a commit.
- Never invent a change that is not present in the log.

No lead paragraph, no prose, no hashes or author names. If a change only
matters to the project's maintainers, keep its line factual and terse.
