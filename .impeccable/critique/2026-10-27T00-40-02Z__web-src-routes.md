## Design specificity verdict

**The Quiet Workspace fits Annalist.** The register leads with a repository, its latest generation outcome, its automation configuration, and the next action. Those are the product’s actual concerns—not generic dashboard metrics or marketing claims.

The ledger identity, warm paper/charcoal themes, copper actions, and labeled outcomes hold together across desktop and mobile. Conventional form controls are appropriate here. **The remaining problems call for safer interactions and less configuration density, not another visual direction.**

## What’s working

- **Outcomes carry operational meaning.** Published, Failed, Cached, and No runs yet are distinguishable through text and icons—not color alone. Failure guidance sits next to the affected repository.
- **Publication safety is clear.** A real frontend preview reported “Nothing was published.” Rendered/raw views worked, and overwrite publication exposed explicit confirmation with a working Cancel action.
- **The approved identity survives the supporting screens.** Desktop light and mobile dark views retain the ledger/wordmark, readable labels, and quiet navigation without adding SaaS chrome or promotional sections.

## Priority issues

### 1. [P1] Repository discovery removes the way to skip setup

**Where:** `/setup`, step 3, after **Load repositories**.  
**Source:** `web/src/routes/setup/+page.svelte:606–903`.

With no repository selected, **Add 0 selected** is disabled, while **Skip for now** and **Continue to tone** are absent. Filtering to zero results also leaves no onward action. Returning to the completed platform step and continuing does not restore the skip control.

**Impact:** The operator must restart the wizard or add a repository they did not intend to add. Reloading and choosing Skip *before* loading is a working but undiscoverable workaround.

**Fix:** Keep a visible skip/continue path after discovery, including empty and filtered results. Adding a repository must not be a prerequisite for finishing setup.

**Suggested command:** `$impeccable harden`

Captured evidence: `.impeccable/critique/evidence/2026-10-26-setup-discovery-trap.png` in the feature worktree.

### 2. [P2] Manual entry defaults to an unavailable platform

**Where:** `/repos/add`, **Manual entry → Platform**.  
**Source:** `web/src/routes/repos/add/+page.svelte:36–37, 54–56, 165`.

The Forgejo-only fixture correctly selects Forgejo for discovery and disables the GitHub discovery tab—but manual entry starts on **github**.

**Impact:** Operators must notice and correct a contradictory default before adding a repository.

**Fix:** Initialize manual entry from configured platforms. Make unavailable choices disabled or explicitly explain why they remain selectable.

**Suggested command:** `$impeccable harden`

### 3. [P2] Navigating away silently discards settings edits

**Where:** `/settings`, especially **Instructions**.  
**Source:** `web/src/routes/settings/+page.svelte:129–151, 308–318, 418–422`.

**Reproduced:** Entered a unique unsaved instruction draft, followed the Repositories link, then returned to Settings. No leave prompt appeared; the draft was gone and the original value had returned.

**Impact:** A routine context switch can destroy substantial writing/configuration work.

**Fix:** Track dirty state and warn before leaving, or provide recoverable drafts. Keep Save/Discard reachable on the long mobile form.

**Suggested command:** `$impeccable harden`

### 4. [P3] The 404 page emphasizes an ineffective retry

**Where:** Unknown routes, **Try again**.  
**Source:** `web/src/routes/+error.svelte:25–43`.

**Reproduced:** Try again reloads the same unavailable address. **View repositories** successfully recovers, but is secondary.

**Impact:** The emphasized action repeats a known failure instead of helping the operator leave it.

**Fix:** Make View repositories primary on 404s. Reserve retry for errors that can plausibly resolve on reload.

**Suggested command:** `$impeccable clarify`

## Cognitive load

**Moderate: two checklist failures.**

- **Pass:** single focus, related grouping, visual hierarchy, one decision at a time, working-memory support, and progressive disclosure—with a caveat that advanced settings remain largely exposed.
- **Fail — chunking:** the commit-type filter presents 11 checkboxes in one group.
- **Fail — minimal choices:** those 11 choices are visible together. The tone selector also contains five options when opened, but its compact native control and domain-sized presets are less concerning than the always-expanded type list.

Keep the common writing decisions prominent; group less-used type filters and model tuning rather than removing capabilities.

## Emotional journey

Token entry explains its purpose and setup progress establishes confidence. **Load repositories is the sharpest confidence drop:** a previously available exit disappears without explanation.

Generation restores confidence through preview-first behavior, explicit “nothing published” feedback, and cancellable overwrite consent. Setup can finish successfully through the pre-discovery skip path. The 404 page is legible, but its primary action weakens the recovery moment.

## Persona red flags

- **Alex — power user:** Batch intake is useful, but existing repositories require individual management. No visible accelerators were found. This is an efficiency observation—not a recommendation to add shortcut chrome.
- **Sam — accessibility-dependent operator:** A disabled Add action with no onward control blocks the setup task regardless of input method. Labels, text-bearing statuses, and source-level focus provisions are present; keyboard-only and screen-reader behavior were not audited.
- **Jordan — first-time operator:** Nothing explains how to escape loaded discovery without adding a repository. The contradictory manual-platform default compounds confusion; “thinking level,” token limits, and lite/deep still assume model-provider knowledge.

## Minor observations

- Global settings are long on mobile; the summary and Save action require considerable scrolling.
- Platform setup repeats **Configured / Not configured** as both subtitle and badge. Keep one representation.
- The 11 commit-type choices are legitimate functionality, but less-common types could be disclosed separately.

## Questions to consider

- Could setup recognize already-managed repositories as sufficient progress rather than making a new addition the only onward path after discovery?
- Should global settings lead with release-writing decisions and reveal provider/model tuning only when needed?
