## Design Specificity Verdict

### LLM assessment
**Strong visual authorship; incomplete operational execution.** Annalist is not category-interchangeable on the public surface. The Release Trace Wall turns commit subjects into a visible webhook → processing → note proof story, and the thermal-paper output plus distinct voice samples make the product mechanism tangible. Explicit `Synthetic` labels preserve trust. Self-hosting copy names GitHub, Forgejo, Docker, `ADMIN_TOKEN`, OpenAI-compatible endpoints, and platform credentials.

The console dilutes that specificity. The same three-node Source/Shape/Proof rail appears above repositories, source intake, and settings even when it reports no live state or unlocks no decision. More importantly, the classes that should translate the visual concept into operational state are used but not defined in `web/src/app.css`, so the promise that states are legible at a glance is incomplete.

## Overall Impression

The landing page feels deliberate, technically literate, and trustworthy. The first-run path has unusually good scaffolding for a self-hosted tool. The biggest opportunity is to make the console operationally truthful: every status must be visually defined, every branch must either complete or state why it cannot, and high-impact settings/actions must be recoverable. Right now the product’s strongest story is more reliable as persuasion than as day-to-day operations.

## What’s Working

1. **Mechanism instead of generic AI imagery.** `ForgeDemo.svelte` shows real product-shaped inputs and output: synthetic commit subjects, stages, and a note proof. The route labels synthetic inputs/output rather than implying customer activity.
2. **Self-hosting persuasion is specific.** The public route explains both forges, the Docker image, `ADMIN_TOKEN`, LLM endpoint, credentials, examples, and zero-touch behavior. It earns the operator’s next click without fabricated metrics or testimonials.
3. **Accessibility foundation is solid.** Native labelled controls, semantic headings, visible focus treatment, live status areas, 44px minimum controls, wrapping long names/output, reduced-motion handling, and visibility-paused trace motion are all present.

## Priority Issues

### [P1] Restore missing console component and state styles

**Where:** `web/src/app.css`; consumed by `/repos`, `/repos/add`, and `/settings`.

**What:** The routes use `.mode-choice`, `.mode-choice--active`, `.mode-choice--danger`, `.status--healthy`, `.status--quiet`, `.status-active`, `.status-ready`, `.status-muted`, `.signal-dot--healthy`, `.signal-dot--muted`, `.signal-dot--error`, `.trace-panel`, `.section-head__lede`, and `.panel--error`, but no matching definitions exist under `web/src`.

**Why it matters:** Disabled repositories can retain a cyan signal, configured states do not receive their intended green semantic treatment, and destructive **Overwrite** lacks a robust selected/danger treatment. Operators lose at-a-glance state recognition and hierarchy.

**Fix:** Define these classes with the named tokens, text-plus-shape differentiation, 44px targets, and focus states, or replace every use with existing utilities. Verify success, empty, error, disabled, selected, and overwrite states across all three routes.

**Suggested command:** `$impeccable audit` or `$impeccable polish`

### [P1] Make “Continue anyway” actually continue setup

**Where:** `/setup`, the no-platform warning and **Continue anyway** in `web/src/routes/setup/+page.svelte` around lines 516–520; the next station presents only **Go back and connect a platform** around lines 549–552.

**What:** The UI says the operator can continue and configure things later, then advances to a repository station that cannot load or skip to voice/completion.

**Why it matters:** A deliberate deferral becomes a dead end during first-run activation. The promise and the state disagree at the exact moment a self-hosting operator is uncertain.

**Fix:** Either remove the promise and keep the operator at the platform station, or allow explicitly incomplete setup to advance to voice/completion with persistent “No platform connected — automation inactive” status and a direct return action.

**Suggested command:** `$impeccable harden` or `$impeccable onboard`

### [P1] Preserve the valid deterministic temperature value

**Where:** Global `/settings` and per-repository settings on `/repos`; `web/src/routes/settings/+page.svelte` around line 55 and `web/src/routes/repos/+page.svelte` around line 110.

**What:** Both forms explain `0 = deterministic` but save via `parseFloat(value) || null`. Because `0` is falsy, the payload becomes `null`, indistinguishable from inherit/server default. The local proof can still display 0 before save.

**Why it matters:** Voice control is Annalist’s differentiator. An operator can choose a valid, explicitly explained value and silently get different generation behavior.

**Fix:** Parse with a finite/NaN check so 0 remains valid; reject malformed input inline; after save show the persisted/effective temperature rather than only form state.

**Suggested command:** `$impeccable harden` or `$impeccable clarify`

### [P2] Give batch repository intake item-level recovery

**Where:** `/repos/add` and setup station 3; sequential `addRepo` loops in `web/src/routes/repos/add/+page.svelte` and `web/src/routes/setup/+page.svelte`.

**What:** If an earlier repository succeeds and a later request fails, the UI shows one generic error and keeps no completed/failed result list. Retrying repeats every selected request.

**Why it matters:** A batch workflow creates a reconciliation exercise instead of saving time. Operators cannot identify partial success or retry only unresolved repositories.

**Fix:** Track pending/success/failure per row, show names and completed count, refresh inventory after partial success, and retry only unresolved items.

**Suggested command:** `$impeccable harden` or `$impeccable audit`

### [P2] Replace static console trace mastheads with live route summaries

**Where:** `.repo-trace` on `/repos`, `.intake-trace` on `/repos/add`, and `.settings-trace` on `/settings`.

**What:** Each route leads with the same three-node Source/Shape/Proof rail before live inventory, selection, or configuration. On mobile it becomes three tall nodes before the task.

**Why it matters:** The landing needs a persuasive story; returning operators need current condition, task, and next action. Noninteractive process diagrams add scroll and decoding without changing a decision.

**Fix:** Keep the full trace on `/`; replace console rails with compact live summaries such as “12 repos / 9 enabled,” “GitHub connected / 34 selectable,” or “model reachable / Forgejo missing,” followed immediately by the task.

**Suggested command:** `$impeccable distill` or `$impeccable layout`

## Persona Red Flags

### Alex — impatient power operator

Alex opens `/repos/add` to add several sources. Each selected repo is sent sequentially; a partial failure has no individual result or retry set. `/repos` has no batch settings path, and static trace rails consume task space before inventory.

### Sam — keyboard/screen-reader operator

Setup’s labelled native fields, focus, and status text are strong. `/repos/add` uses `role="tablist"`/`role="tab"` for GitHub/Forgejo but supplies neither tab-panel relationships (`aria-controls`/`role="tabpanel"`) nor arrow-key tab behavior. Native buttons remain activatable, but announced tab semantics promise more than the interaction provides.

## Minor Observations

- At 390px, the sticky shell is about 108px tall: brand/subtitle occupy one row and **Setup** wraps to a sparse second row. Controls remain usable, but the shell consumes meaningful vertical space before first-run input.
- Landing Docker **Copy** silently discards clipboard failure in `copyDocker()`. Add a fallback such as “Copy unavailable — select the command.”
- `+layout.svelte` labels a localStorage onboarding hint **SETUP READY**. It can outlive changed platform/configuration state; label it local onboarding completion or query live readiness.
- `MarkdownPreview.svelte` still uses one-off legacy colors (`#ff7b00`, `#2a2e35`, `#f3f0ec`, etc.) instead of the named Release Trace Wall tokens.
- Public and setup type hierarchy is authored and clear; repository/settings headings rely on absent console component classes and therefore lose the same authored hierarchy.
